# AI社員 設計図ライブラリ（AI社員室 週1配信の在庫）

AI社員室（2,980円/月）の会員特典「毎週1通の設計図」の原稿置き場。
ここにある Markdown を、毎週1本 note の会員限定記事として公開する。

## 運用ルール
- ファイル名: `NN-<division>-<name>.md`（NN は配信順）。
- 状態は先頭の `status:` 行で管理する。`draft`（AI下書き）→ `reviewed`（オーナー確認済）→ `published`（公開済・note URL を追記）。
- **draft のまま公開しない。** 下書きは各AI社員の一行説明（index.html）から起こしたもので、実際の運用プロンプトはオーナーが手を入れて仕上げる。
- 1本あたり 2,000〜3,000字。読者は「プログラミングは知らないが、自分の仕事をAIに任せたい個人事業主」。
- 実在の顧客名・実データは書かない。例はすべて架空。

## 1本の構成（テンプレート）

```
status: draft
division: insta-company
member: writer
title: リール台本ライター

# 設計図 No.01 ｜ リール台本ライター（insta-company / writer）

## この社員がやること
（3行で。何を受け取り、何を出すか）

## 向いている人・仕事
（箇条書き3〜5個）

## 判断基準
（「こういう時はこうする」を5個。AI社員が迷わないための線引き）

## 雇い方（そのまま貼るプロンプト）
（CLAUDE.md / カスタム指示にそのまま貼れる形。役割・判断基準・出力形式・やらないこと）

## 使ってみる
（依頼例3つ ＋ 期待する出力の例1つ）

## よくある失敗と直し方
（3つ）

## 次に雇うなら
（相性のいい別の設計図を1〜2本）
```

## 配信の流れ（週1）
1. 日曜夜: AI社員（book-company / note 担当）が次の1本を draft で作成し、ブランチにコミット。
2. 月曜朝: オーナーがスマホで読んで手直し → `status: reviewed`。
3. note 会員限定で公開 → `status: published` と URL を追記。
4. 公開告知は `docs/posts/` の投稿案フォーマットで Threads / Instagram に。
